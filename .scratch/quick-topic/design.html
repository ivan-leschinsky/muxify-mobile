Muxify Mobile: Topics and Sessions tabs, Go to and New Topic

What we build, so that the phone starts a Topic from a Session Path and opens a Session as fast as the Mac does. Mock screens use the phone's colours from src/constants/app-theme.ts.

Four parts. (1) The Host Screen gets the Mac's Topics and Sessions tabs. (2) In the Topics tab, the card you are in shows under a closed Bench row, as on the Mac. (3) A Liquid Glass bar at the bottom holds the Go to field and a ＋ menu. (4) New Topic follows the Mac: title, then a Session Path. The Host CLI gets one new verb, session-paths with no Topic, and three small additions.

1. Host Screen: Topics and Sessions tabs

The same two views as the Mac's Sidebar (muxify docs/configuration.md:1692, :1720-1730). They replace the stacked lists of Configure panels.

Rules

  • The Host's Config decides which tabs show: sidebar.topics and sidebar.sessions, read from environment show. One setting for the Mac and the phone. Configure panels goes.
  • A Host CLI with no Topics shows only the Sessions tab.
  • The phone remembers the last tab for each Host.
  • Switch with a tap on the tab, or ⌥⌘T on an iPad keyboard. No swipe: a horizontal swipe on a Topic card is its swipe action (src/app/hosts/[id].tsx:254).
  • Recent Sessions stops being a list. It ranks the Go to list before you type.
  • New Session and New Topic leave the Options menu. ＋ takes their place.

Bench peek

  • While the Bench row is closed, the card of the Attach's Topic shows under it. When the Attach's Session is in No Topic, that Session shows there. This is the Mac's rule (Sources/Muxify/Topics/TopicsModel.swift:676-698).
  • Today the phone hides every Bench card while the row is closed (src/domain/host-screen.ts:303-307).

2. The Liquid Glass bar and Go to

A native bottom toolbar on the Host Screen, in both tabs: <Stack.Toolbar placement="bottom"> with Stack.Toolbar.SearchBarSlot for the field from <Stack.SearchBar>, a Spacer, and a Menu for ＋. Expo Router 57.0.21 has all four. The search field in the bar needs iOS 26, which is the lowest iOS version the app supports.

The Go to list

  • One list, as on the Mac (ADR 0045): running Sessions (■) with their Topic, Session Paths (□), Worktrees (⑂). A typed path (leading ~) is the last row.
  • Ranking: the Host ranks it with --query, with the Mac's fuzzy match and last visit. With an empty field: last visit.
  • Running Sessions come from the phone's tmux Listing joined with environment show.

A tap on a row

  • Running Session: the Attach switches to it, with the Title Sheet rules for Topic membership.
  • Session Path: go to its No Topic Session, or make one there with session new <dir> --name …, as ↩ in Go to… on the Mac (WorkspaceStore.swift:190-194).
  • Long press on a Session Path: “New Session here” makes another one with a +2 name, as ⌘↩ on the Mac.

Where the bar is not

  • Home, which has no Host. The Terminal, where the Key Row and the keyboard are at the bottom.
  • Edit mode and the Fill Place sheet hide it.

3. New Topic

The Mac's ⌘N, in one sheet: title, then a Session Path.

＋ → New Topic→title→↩→“mob”→tap rowSession open, Topic on top of the Bench

Rules

  • A tap on a running Session moves it into the Topic, as ↩ on a ■ row on the Mac.
  • Add later, or leaving the sheet, keeps the Empty Topic, as on the Mac.
  • Both writes carry a Request id, as today (ADR 0021). The Session name is <path>/<topic slug>, made by the Host.
  • This replaces today's New Topic → Save → Add a Session sheets (src/app/topic-form.tsx, src/app/topic-add-session.tsx).

5. Slow Host or no Connection

  • The phone keeps the last path list for each Host and shows it at once. A new read replaces it in the background, with no jump under the finger.
  • The Host CLI answers from the Mac's cache (~/.local/state/muxify/session-paths/<env>.json) and then refreshes it, so a slow git worktree list does not hold the list.
  • No Connection: the list shows from the cache with “Connecting to mac-studio…”. A pick waits on screen and goes when the Connection is up. It never goes after you leave.
  • No answer: the same Request goes one more time. Then the Host Write is unsure, with Check (ADR 0020, 0021).

6. The work

Host CLI (desktop repo)

  1. muxify session-paths [--query q] --json with no target: Session Paths and Worktrees, the rows of topic session-paths less in_this_topic, answered from the cache. Today the verb needs a Topic, Window or Pane (CLIVerbs.swift:468-471).
  2. Last visit in muxify.db, moved from UserDefaults (VisitLog.swift). --query ranks with the Mac's PickList. A visit from the phone counts on the Mac.
  3. sidebar.topics and sidebar.sessions in the environment show answer, next to the Tags.
  4. Capability name "session-paths" next to "request" (RequestInvocation.swift:687).
  5. Check that session new takes --request.
  6. Mac New Topic refuses an empty title, in place of “Untitled”.

Phone

  1. Topics and Sessions tabs on the Host Screen; Configure panels and the Options menu entries go.
  2. Bench peek for the Attach's Topic or No Topic Session.
  3. Bottom bar: Go to field and ＋ menu.
  4. Go to list, ranking from the Host, cache per Host.
  5. One New Topic sheet: title, then Add a Session.
  6. New Session at a folder through session new.
  7. ⌘P, ⌘N, ⌥⌘T and the list keys.
  8. On an old Host CLI: today's sheets.
  9. CONTEXT.md: Go to, the tabs, the Bench peek. New Session (a name, no folder) goes.

7. Decisions

Decided: the Terminal's chooser stays as it is

The Title Sheet in the Terminal keeps its Windows / Sessions / Topics switch, as today. Only the Host Screen gets the two tabs.

Decided: an empty title is refused, on the phone and on the Mac

The phone keeps its rule: Return does nothing until the title has text, and the field says “Give the Topic a title.” The Mac changes to match: New Topic (⌘N) with an empty title makes nothing, in place of an “Untitled” Topic (PaletteFlow.swift:157).

Decided: iOS 26 and later only

The app supports iOS 26 and later only. So the search field always shows in the bottom bar, and there is no fallback ⌕ button.
